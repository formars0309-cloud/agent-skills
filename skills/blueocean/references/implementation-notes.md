# 구현·API 참고 — 스크립트를 고치거나 결과가 이상할 때

> 2026-09-27 `SKILL.md`에서 옮겨 온 원문이다(내용 변경 없음).

## API 규격이 2026년에 바뀌었다

신규 신청은 **NAVER API HUB**(네이버 클라우드 플랫폼)를 사용한다. 기존 개발자센터에서 2026년 7월 31일 이전 신청한 검색·검색어 트렌드 API는 공식 공지상 2027년 6월 30일까지 지원된다. 이 스크립트는 API HUB 규격을 사용하므로 구형 인증정보를 혼용하지 않는다.

공식 공지: https://developers.naver.com/notice/article/32530

| | 기존 개발자센터 | 현행 |
|---|---|---|
| 헤더 | `X-Naver-Client-Id` / `-Secret` | `X-NCP-APIGW-API-KEY-ID` / `X-NCP-APIGW-API-KEY` |
| 검색 | `openapi.naver.com/v1/search/blog.json` | `naverapihub.apigw.ntruss.com/search/v1/blog` |
| 트렌드 | `openapi.naver.com/v1/datalab/search` | `naverapihub.apigw.ntruss.com/search-trend/v1/search` |

트렌드 경로는 **하이픈이 들어간 `search-trend`** 다. `datalab/*` 계열은 전부 404 다.
검색광고 API(`api.searchad.naver.com`)는 이관 대상이 아니라 HMAC 방식 그대로다.

응답 코드로 원인을 구분한다.

- `404` — 그런 경로가 없다. 오타이거나 규격이 다르다
- `401` — 인증정보와 신청 API를 확인한다. 원인을 상태 코드만으로 단정하지 않는다
- `429` — 한도 초과. 호출 간격을 늘린다

## 추세 지표를 짧은 창으로 내지 마라

12개월치의 '최근 3개월 / 첫 3개월' 비교는 **계절 키워드에서 거짓 하락을 만든다.**
본인부담상한제는 매년 8~9월에 환급 안내문이 나가 그때만 5배로 뛴다.
12개월 창의 앞쪽에 그 스파이크가 걸리면 0.24, 급락으로 찍힌다.
24개월을 받아 같은 달끼리 비교하면 1.74, 성장 중이다.

스크립트는 한국 시간 기준 완료된 월 24개를 조회해 이전 12개월 평균과 최근 12개월 평균을 비교한다. 24개 월의 누락·중복이 있으면 원자료만 보존하고 전년 대비 계산을 생략한다. 직접 계산할 일이 있어도 이 방식을 쓴다.

## 구현 보완 — 2026-09-20

- 광고성은 상위 10건의 거친 추정이다. 일반 제목·요약의 `병원`, `센터`, `상담`만으로는 광고로 판정하지 않는다. 의료기관명으로 끝나는 블로그 이름, 상담 신청·무료 상담·협찬 등 명시적인 신호를 사용한다. 기관 계정도 정보 글을 쓸 수 있으므로 오판 가능성은 남는다.
- JSON의 각 행에 `monthly`(월별 상대 검색 지수), `trendWindow`, `trendComplete`를 보존한다. 월별 지수는 절대 검색량이 아니다.
- JSON의 `warnings`에 조회 실패·추세 누락을 기록하고, 포화도 측정 불가 키워드는 `unmeasured`에 보존한다. `measuredCount`는 순위 산출에 성공한 개수다. 뉴스·추세 등 보조 지표까지 모두 성공했다는 뜻은 아니다.
- 통신 오류·HTTP 429·5xx는 최대 3회 시도하고, 요청마다 30초 제한을 둔다. 인증·경로 오류는 재시도하지 않는다.
- 수익점수는 검색광고 경쟁도·깊이에 기반한 비교용 휴리스틱이다. 실제 CPC·애드포스트 수익을 측정하지 않는다. 광고 CTR은 표시만 하며 점수에는 쓰지 않는다.
- 추세·열기는 정렬 점수에 들어가지 않는 참고 정보다. `--hot`과 `--revenue`를 함께 쓰면 수익 정렬이 우선하고 열기는 조회하지 않는다.
