# 네이버 메이트

목표는 적합한 네이버 채널에서 독자의 질문에 더 나은 답을 쌓고, 공식 기준과 실제 관측으로 개선하는 것이다. 선정 확률·합격선·수익을 보장하지 않는다. 원고 작성 스킬을 대체하지 않으며 전략과 인용 준비 상태를 판단한다.

## 시작: 정책과 채널을 먼저 구분한다

[공식 기준](references/official-baseline.md)을 읽고 현재 공식 홈페이지·고객센터·해당 서비스 공지를 확인한다. 정책 확인일을 결과에 남긴다. 2026-09-18 기록에서는 2026년 6~12월 베타이며, 종료 후에는 운영 연장·새 기준 확인 전 선정 일정이나 지원금을 확정하지 않는다. 공식 페이지를 확인하지 못하면 마지막 확인일과 미확인 항목을 적고 콘텐츠 개선은 계속한다.

다음 네 가지를 구분해 보고한다.
- **공식 사실:** URL과 확인일이 있는 선정·집계 규칙.
- **외부 연구·다른 플랫폼 지침:** 실험한 엔진·시점·측정 대상과 한계를 적는다. 네이버 공식 기준으로 승격하지 않는다.
- **관측:** 해당 채널·질문·기간에서 실제 본 수치와 화면.
- **운영 가설:** 주제 선택, 글 구성, 발행량, 평가 기준. 공식 알고리즘으로 단정하지 않는다.

대상 채널 URL·서비스, 최근 주제와 독자, 목표, 인용수 접근 여부, 검수 가능한 시간과 자료를 기존 문맥에서 확인한다. 빠진 입력은 미확인으로 두고 일반 전략·초안 검토를 먼저 진행한다. 특정 채널 판정에 꼭 필요한 정보만 요청한다. 임의로 사용자 블로그를 목표 채널로 고르지 않는다.

## 전략 우선순위

### 1. 목표와 맞는 채널을 택한다

- **기존 채널:** 최근 글과 독자가 목표 주제에 맞으면 관련 글의 갱신·보완부터 검토한다. 최근 글 표본은 예컨대 10~20편에서 시작하되 표본 크기·선택법을 적는다. 비율을 합격 기준으로 만들지 않는다.
- **신규 채널:** 적합한 기존 채널이 없고 장기 운영 여력이 있을 때 후보로 제안한다. 신규가 유리하다는 근거 없는 가정으로 기본 선택하지 않는다.
- **독립 사이트:** 메이트 대상 서비스인지 현재 공지를 확인한다. 별도 네이버 채널을 쓴다면 그 글 자체로 질문에 답하게 편집한다. 가입·외부 방문만 유도하는 미완성 요약문이나 복제 글로 채우지 않는다. 기존 사이트 이전·채널 주제 변경·신규 개설을 전략 요청만으로 실행하지 않는다.
- **카페:** 개인 글 인용과 게시판 평가·카페 지원을 분리한다. 회원 경험의 재사용에는 동의와 공개 범위가 필요하다. 지식iN·프리미엄콘텐츠는 각 서비스 운영 기준을 확인하며 블로그 템플릿을 강제하지 않는다.

### 2. 한 독자군의 해결되지 않은 질문에 답한다

검색어보다 독자가 결정하거나 실행할 일을 먼저 적는다. 후보별로 실제 검색 결과와 원문을 살펴보고, 기존 답에서 빠진 조건·절차·비교·확인 자료를 기록한다. 기본 표본은 질문별 5~10건 정도에서 시작하되 적절히 조정한다. 제목만 보고 본문 품질을 판정하지 않는다.

고를 질문에는 다음이 있어야 한다: 독자의 필요를 보여주는 근거, 기존 답의 구체적인 부족함, 우리가 더할 검증 가능한 가치, 유지·검수 가능성. 이것은 편집 판단이며 네이버 가중치가 아니다. 경쟁이 낮은지 확인하지 않았다면 '블루오션'으로 확정하지 않는다.

키워드 실측이 필요하고 blueocean·title-check가 있으면 보조로 사용한다. API의 total·도메인·관련성을 실제 화면과 대조하고 오류가 있으면 자동 포화도 판정을 버린다. 글 수/검색량/인용수는 서로 다른 지표다. 키워드 조사는 이 스킬의 필수 의존성이 아니다.

### 3. 출처에 없는 도움을 정직하게 더한다

각 글마다 '기존 답을 본 독자가 이 글에서 추가로 얻는 것'을 한 문장으로 명시한다.
- 실제 경험: 무엇을 언제 어떤 조건에서 했는지, 결과·실패·한계를 확인 가능한 범위에서 쓴다.
- 직접 경험이 없을 때: 공식 자료 간 조건 대조, 확인된 예외, 직접 검증한 계산·도구, 서류 점검표, 다음 행동을 고르는 순서도 등을 만든다. 공식 사실과 작성자의 해석을 분리하고 '공식 문서 기반 정리'처럼 역할을 밝힌다.
- 출처 링크를 붙인 재요약만으로 고유 가치가 생겼다고 판정하지 않는다. 직접 하지 않은 실험·인터뷰·진료·육아를 꾸미거나 공개 후기 몇 개를 메타분석으로 부르지 않는다.
- AI는 조사 보조·구조화·편집에 쓸 수 있다. 생성한 사실과 출처를 사람이 확인하는 단계가 필요하다. AI 미사용처럼 위장하는 것을 목표로 삼지 않는다.

가독성을 위해 첫 부분에 질문의 답과 적용 조건을 두고, 예외·다음 행동·근거를 연결한다. 표·목록·요약은 필요한 곳에 사용한다. 모든 글에 3줄 요약, 특정 글자 수, 건조체를 강제하지 않는다. 실제 경험의 맥락과 독자에게 필요한 감정 표현을 지우지 않는다. 이미지의 핵심 정보는 텍스트로도 제공한다.

원문 링크·자료 기준일·작성/실질 수정일·광고나 협찬 관계를 필요한 위치에 표시한다. 정보가 바뀌었을 때 갱신하며 내용 변경 없이 날짜만 바꾸지 않는다. 의료·법률 등 고위험 분야는 해당 검수 절차를 적용한다. 의료 글은 의료인 승인 상태와 경험의 진실성을 별도로 확인한다. 공개 허가와 실제 의료진 검토 완료를 구분하고 사용자·프로젝트의 발행 규칙을 따른다. 자동 검수를 의료진 승인으로 표시하지 않으며 사적인 아이 정보를 소재로 쓰지 않는다.

### 4. GEO로 답변의 인용 가능성과 정확성을 함께 개선한다

GEO(Generative Engine Optimization, 생성형 검색 최적화)는 AI가 생성하는 답변에서 콘텐츠가 발견·활용·출처로 연결되는 방식을 개선하는 접근이다. 메이트 선정은 별도의 종합평가다. GEO를 SEO(검색엔진 최적화)의 폐기나 선정 보장 공식으로 설명하지 않는다.

전략 설계·GEO 검수 시 [GEO 적용 가이드](references/geo-playbook.md)를 읽는다. 실행 우선순위는 **검색 가능한 공개 글 → 독자 질문에 대한 고유한 답 → 근거와 조건을 보존한 문단 → 실제 인용 관측**이다. 이는 작업을 위한 점검 순서이지 네이버 내부 처리 단계의 공개 설명이 아니다.

- 주 질문과 비교·절차·예외 등의 후속 질문을 연결한다. 같은 답을 표현만 바꾼 여러 글로 늘리지 않는다.
- 중요한 문단만 읽어도 대상·답·조건·기준일·근거를 이해할 수 있게 한다. 첫 답과 제한 조건을 떼어 놓지 않는다. 모든 문단에 같은 형식이나 길이를 강제하지 않는다.
- 인용·통계는 실제로 주장에 필요한 근거만 사용한다. 원문의 수치·분모·기간·한정어를 보존한다. 인용 개수나 권위적인 말투로 신뢰도를 채점하지 않는다.
- 원고에서는 인용 준비 상태를, 공개 후에는 실제 출처 링크와 답변의 의미 보존을 따로 검수한다. AI 인용이 늘어도 독자 유입·정확성·메이트 선정이 함께 늘었다고 가정하지 않는다.
- 네이버 채널에서 수정할 수 있는 본문·출처·이미지 설명부터 개선한다. robots.txt·스키마·llms.txt를 메이트 필수 조건으로 만들지 않는다. 독립 사이트의 기술 설정은 그 사이트와 해당 엔진의 공식 지침으로 별도 판단한다.

## 30일 실험과 월별 평가

채널과 검수 여력이 확인되면 다음을 출발 가설로 조정한다. 미확인 상태에서도 임시 수량·시간 가정을 명시한 준비 계획은 만들 수 있으나 채널별 진단 완료나 발행 계획 확정으로 표시하지 않는다. 고정 발행량·분량은 선정 조건이 아니다.

| 기간 | 준비할 결과 |
|---|---|
| 1주 | 채널·정책·인용 기준선 확인, 독자 질문 10개 안팎 탐색, 근거와 고유 가치가 있는 3~5개 선택 |
| 2~3주 | 검수 가능한 4편 안팎의 새 글 또는 기존 글 실질 개선. 답·근거·조건 배치 등 비교할 변화 요소와 기준선을 미리 기록 |
| 4주 | 관측 가능한 반응·정정·제작 시간을 검토하고 1~2편 개선, 다음 달 유지·수정할 가설 결정 |

원고 준비와 공개 발행을 구분한다. 공개 요청과 필요한 승인 없이는 초안·검수까지만 한다. 실험 관측 시작점은 실제 공개/실질 수정일이다. 초안만 만든 달을 발행 성과 평가에 넣지 않는다.

[측정 규칙](references/measurement.md)을 적용해 누적·당월·전전월 인용, 검색 표본, 독자 반응, 선정 여부, 작업 시간을 분리한다. 지표 미제공을 0으로 취급하지 않는다. 글별 인용을 볼 수 없으면 채널 인용 증가를 특정 글의 성과로 단정하지 않는다.

현재 전전월 규칙에서 활동 월 M의 일반 선정 관련 관측은 M+2월이다. 60~90일에 검토하되 실제 달력·집계기간과 베타 운영 기간을 적용한다. 30일 미선정으로 실패 판정하지 않는다. 반대로 선정됐다는 이유만으로 그 형식이 원인이라고 단정하지 않는다.

관측과 근거가 충분할 때만 확대한다. 변화가 없으면 접근·검색 가능성·질문 적합성·고유 가치를 차례로 점검하고 작은 수정 실험을 택한다. 지원금 없이도 독자 효용과 유지 비용이 맞는지 평가한다. 지원금은 확정 매출로 잡지 않는다.

## 검수와 결과물

전략 요청에는 **정책 확인 요약 → 채널 판단 → 우선 질문과 추가 가치 → 30일 계획 → 관측표·평가일 → 미확인 사항**을 필요한 만큼 낸다. 대상 서비스가 없는 경우 직접 선정 실험을 할 수 없다는 점과 가능한 대체 작업을 먼저 밝히고, 무관한 선정 관측표는 생략한다. 원고 검수 요청에는 전략 전체를 반복하지 말고 해당 글의 고유 가치·근거·역할 표시·질문 해결·문단 단독 의미 보존·수정 제안에 집중한다. 공개 글이면 인용 관측 여부와 인용 정확성을 추가한다. 수치가 없으면 수치를 만들지 않는다.

준비 완료는 전략과 검수의 완료를 의미한다. 실제 선정 완료와 구별한다. 게시 빈도·키워드 밀도·인용수 목표를 비공개 합격선처럼 쓰지 않는다. 자가 검색 반복·품앗이 클릭/댓글·다계정 반응·가짜 경험·유사 글 양산으로 지표를 만들지 않는다.

이 스킬을 만든 현자 비교의 채택·기각 근거는 [전략 결정 기록](references/strategy-decisions.md)에 있다. 매 실행마다 현자를 재호출할 필요는 없다. 사용자 요청이나 전략의 큰 재검토가 필요할 때만 실행하고, 모델 다수결을 공식 근거 대신 쓰지 않는다.
