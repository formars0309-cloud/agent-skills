# 네이버 블로그 글쓰기

## 프로젝트 연결

1. 현재 프로젝트의 AGENTS.md와 네이버 전용 스킬 또는 프로필을 먼저 읽는다. 그곳이 지정한 독자·브랜드·원천·검수·발행 권한을 적용한다.
2. 프로필은 프로젝트에 한 벌만 둔다. 아래 항목을 기존 문서에 연결하고, 공통 규칙을 복사하지 않는다.
   - 대상 계정·블로그명, 독자와 글의 목적, 어조와 금지 표현
   - 기준 원문·근거 확인 방법, 저자 경력과 검토 상태 표기
   - 카테고리·주제, 출처·원문 링크 정책
   - 소제목·강조·구분선, 이미지 종류·수·브랜드 디자인
   - 산출물 위치·생성기·검증 명령, 집필·검수 역할
   - 임시저장·공개 권한과 완료 조건
3. 프로젝트 프로필이 없으면 확인된 내용으로 중립적인 로컬 초안을 진행하고 가정을 기록한다. 실제 계정·대상·공개 권한이 확인되지 않은 업로드·발행은 진행하지 않는다.
4. 한 프로젝트의 의료 기준, 카드 수, 카테고리 ID, 자동 발행 허가를 다른 프로젝트에 옮기지 않는다. 사용자 최신 지시와 프로젝트 규칙이 공통 기본값보다 우선한다.

## 집필·변환

- 글 한 편이 답할 독자의 질문을 정하고 제목·도입·결론이 그 질문에 답하도록 구성한다. 검색량·순위·노출 효과를 실측 없이 주장하지 않는다.
- 파생 글은 기준 원문과 검수 상태를 먼저 확인한다. 질문을 좁혀도 수치·단위·조건·예외·부정·인용과 결론의 한정어를 유지한다. 새 주장이 필요하면 원천 확인 단계로 돌아간다.
- 실제 경험·사례·자격·검토일을 만들어 넣지 않는다. 인용 출처는 해당 주장과 연결하고 링크 목적지를 확인한다.
- 프로젝트의 섹션 순서를 따른다. 지정이 없으면 독자의 질문 → 핵심 답 → 근거와 실행에 필요한 설명 → 한계·주의 → 출처 순서로 쓴다.
- [모바일 블로그 가독성](../mobile-blog-readability/SKILL.md)을 읽고 적용한다. 문장 간격·번호 구분·약어 풀이·실제 글자 크기의 정본은 그 스킬이며 이곳에 복제하지 않는다.
- 이미지 수를 채우려고 불필요한 표나 카드를 만들지 않는다. 프로젝트 디자인을 따르고 본문과 이미지의 수치·조건을 대조한다. 작은 이미지 글자만으로 핵심 정보를 전달하지 않는다.
- 완성 이미지는 실제로 열어 한글·잘림·표 셀 대응·빈 공간·모바일 식별성을 확인한다. 승인 자산을 형식 정리만으로 재생성하지 않는다.

## 입력·저장

1. 프로젝트 생성기·검증기가 있으면 사용한다. 원고와 입력용 가이드, 이미지 순서가 일치하는지 확인한다.
2. 사용자가 지정한 브라우저 도구와 작업 탭을 사용한다. 로그인된 계정과 대상 블로그를 실제로 확인한다. Aside를 쓰면 [naver-account](../naver-account/SKILL.md)로 블로그별 전용 프로필을 고르고 계정을 확인한다. 인증은 사용자·프로젝트 권한을 따르며 비밀값을 기록하지 않는다.
3. 제목·본문·이미지·구분선·링크를 입력한다. Markdown 기호나 자리표시자가 독자 화면에 남지 않게 한다. 소제목 프리셋·기본 글자 크기의 효과를 추정하지 않는다.
4. 썸네일·대표 이미지·카테고리·주제를 확인하고 임시저장한 뒤 서버 저장본을 다시 연다. 제목·본문·이미지·링크·간격·서식 유지 여부를 확인한다.
5. 공개는 실제 요청 범위와 프로젝트 권한·검수 조건을 충족할 때만 진행한다. 초안 요청이나 스킬 수정 요청을 공개 허가로 해석하지 않는다. 자동 검수와 실제 전문가 승인은 별도 상태다.
6. 공개한 경우 실제 URL을 재조회하고 모바일 화면까지 확인한다. 기존 글 수정은 공개본과 로컬 차이를 확인하고 복원 가능한 원본을 보존한 뒤 수행한다.

## 완료 기록

기준 원문·대상 계정·산출물 경로, 수행한 검사와 실패·미확인 항목, 실제 저장 또는 공개 상태·URL을 기록한다. 로컬 생성, 업로드, 임시저장, 공개를 구분한다. 저장 응답만으로 재열기나 공개 검증을 완료했다고 보고하지 않는다.
