# 와우 포에버 글쓰기 공통 규칙

네이버 블로그(`codori_game`)와 사이트(`wofwforever.com`)는 **같은 글쓰기 규칙**을 쓴다.
이 파일이 유일한 정본이다. 규칙을 바꿀 때는 이 파일만 고친다.
각 저장소의 `AGENTS.md`에는 채널별 **구현 방법**(글자 크기, 도구, 빌드)만 둔다.

| 채널 | 작업 위치 |
|---|---|
| 네이버 블로그 | `/Users/app/orca/workspaces/애드포스트 정복/WoW-Forever-Naver-blog` |
| 사이트 | `/Users/app/orca/projects/애드포스트 정복/sites/wofwforever` |

채널의 역할과 상호 링크는 두 저장소의 `channel-synergy-plan-20260923.md`를 따른다.
이 파일은 "어떻게 쓰고 보여 주는가"만 다룬다.

## 1. 이미지

- **공식 이미지 우선(2026-09-24 사용자 지정):** 썸네일과 본문 이미지는 블리자드 공식 이미지(공식 뉴스·소개 페이지의 스크린샷·키아트)를 먼저 쓴다.
  공식 이미지가 화면의 주인공이 되게 크게 보이고, 흐린 배경으로만 깔고 끝내지 않는다. 도식(표·비교 카드)은 공식 이미지로 보여 줄 수 없는 정보에만 쓴다.
- 공식 이미지는 크롭·축소와 화면 바깥(또는 가장자리 띠) 문구 합성만 한다. 좌우 반전·색 변경·생성형 AI 재작성은 하지 않는다.
  원본 속 핵심 요소(진영 문장, 직업 아이콘, 라벨)를 설명 띠나 제목으로 가리지 않는다. 가리면 띠를 빼거나 다른 컷을 쓴다.
- 원본 주소·크기·취득일은 공식 이미지 장부(`SOURCES.json`)에, 글마다 어떤 원본을 어떻게 편집했는지는 `assets/SOURCES.md`에 남긴다.
- 한 이미지에는 핵심 메시지 하나만 둔다. 본문과 겹치는 장문 부제, 불필요한 워터마크는 뺀다.
- 고객지원·게임 UI 캡처는 틀에 통째로 축소하지 않는다.
  독자가 눌러야 할 버튼·선택 항목·경고문을 먼저 정하고 원본 화면을 좁게 크롭한다.
- 공식 UI·아이콘·수치·글자는 생성형 AI로 다시 그리지 않는다.
  화면 증거는 원본 픽셀을 크롭·확대하고, 설명 문구는 화면 바깥에 결정형으로 합성한다.
- 생성 이미지(풍경·삽화·마스코트)는 장식이다. 공식 게임 화면이나 사실의 증거로 쓰지 않는다.
- 이미지·표·그래프에만 있는 수치를 두지 않는다. 같은 수치를 본문 문장에도 적는다.
- 390px 폭에서 핵심 문구와 조작 대상이 읽히지 않으면 다시 만든다. 160px·320px 축소본도 연다.
- 블리자드 캐릭터(쓰랄·제이나 등)나 게임 IP를 생성하지 않는다. 마스코트는 승인된 **세린**뿐이다.
- 원본 파일은 보존하고, 크롭·합성 좌표와 문구를 기록해 다시 만들 수 있게 한다.
- **본문 공식 이미지(2026-09-24):** 썸네일과 같은 원본(같은 파일·같은 컷)을 본문에 다시 쓰지 않는다. 본문 이미지는 그 절이 설명하는 화면을 보여 주는 다른 컷이어야 한다.
- 캡션·대체 텍스트에 넣는 숫자는 같은 언어 본문에 있는 것만 쓴다. 캡션에서 새 수치를 처음 알리지 않는다.

## 2. 썸네일

- 글마다 대표 썸네일 한 장을 둔다. 목록·공유 화면에서 가장 먼저 보이는 이미지다.
- 한 장면에 주제 하나만 담는다. 160px 축소본에서도 무엇에 관한 글인지 구분돼야 한다.
- 게임 로고, 블리자드 캐릭터, 공식 원화를 새로 생성하지 않는다.
- 어두운 가죽·금색의 전초기지 분위기(사용자 승인 방향)를 유지한다. 임의로 다른 톤으로 바꾸지 않는다.
- 대체 텍스트를 쓴다. 장면을 설명하되 글 제목을 반복하지 않는다.

## 3. 긴 구분선

- **모든 주요 소제목(H2) 바로 앞에 긴 구분선을 넣는다.** 절과 절이 한눈에 나뉘어야 한다.
- 하이픈, 밑줄, 이미지 선으로 대체하지 않는다.
- 가장 좁은 기준 화면(360px)에서 한 줄로 보여야 한다. 두 줄로 접히면 길이를 줄인다.
- 새 글과 이후 수정하는 기존 글에 적용한다. 구분선 수와 H2 수가 같은지 검사한다.

## 4. 모바일 가독성

기준 화면은 360·390·430px이다. 자동 검사가 통과해도, 지연 로딩이 끝난 뒤 실제 화면을 연다.

- 한 문단에는 한 문장을 기본으로 둔다. 인사도 한 문장으로 쓴다.
- 90자를 넘는 문단을 두지 않는다. 넘으면 문장을 나눈다.
- 소제목에 `01.` 번호를 쓰므로, 순서 있는 절차는 `① ②`, 순서 없는 선택지는 글머리표로 쓴다.
- 처음 나오는 약어·영문 용어는 뜻을 함께 적는다.
- 가로 넘침은 0건이어야 한다. 표는 좁은 화면에서 카드로 바뀌거나 가로 스크롤 없이 읽혀야 한다.
- 제목은 주제목과 부제를 한국어 `｜`(영어·독일어는 첫 `: `)로 한 번만 나눈다.

## 5. 사실과 표기

- 공식 원천을 먼저 확인한다. 공식 한국어 명칭은 공식명 장부를 따르고, 확인하지 못한 이름은 임시 번역이라고 밝힌다.
- 해외 커뮤니티 의견은 출처와 조건을 붙여 소개한다. 직접 플레이한 것처럼 쓰지 않는다.
- 이용자 인용은 원문과 대조한 것만 쓴다(장부만 믿지 않는다).
- 미확정 일정이나 수치를 단정하지 않는다. 기준일과 게임 버전(빌드)을 적는다.
- 지역별 시간·가격·상품 조건은 지역을 명시한다. 한 지역의 조건을 다른 지역에 복사하지 않는다.

## 6. 시각 요소(표·그래프·단계·요점·본문 이미지)

2026-09-24 사용자 요청("글로만 표현돼 있다 → 표·그래프·이미지로 정리")에 따른 채널 공통 원칙이다.
문장만 길게 이어지는 절을 줄이고, 정보의 모양에 맞는 요소 하나로 정리한다.

| 정보의 모양 | 쓸 요소 |
|---|---|
| 수치·조건 비교(가격, 지역별 시간, 사양) | 표 |
| 구성비·크기 비교(점수 구성, 범주별 최대치) | 가로 막대 그래프 |
| 순서가 있는 절차(여는 순서, 설정 단계) | 단계 흐름(① ② ③, 3~6단계) |
| 꼭 기억할 핵심, 주의, 미발표·추정 | 요점 상자(항목 1~4개, 각 한 문장, 절마다 최대 1개) |
| 게임 화면 설명(창, 버튼, 아이콘) | 블리자드 공식 스크린샷 |

- **모든 숫자는 본문 문장에도 적는다.** 표·그래프·단계·요점 상자·캡션에만 있는 수치를 두지 않는다.
- 사이트는 표·그래프를 **글자가 든 그림 파일로 만들지 않는다.** 빌드가 HTML·SVG로 그려 3개 언어·검색·모바일·숫자 자동 대조를 유지한다.
- 공식 이미지는 공식 페이지에 실린 것만 쓰고 크롭·축소만 한다. 변형·합성·AI 편집을 하지 않으며 크레딧(© Blizzard Entertainment와 출처)을 단다.
- 한 글의 본문 이미지는 최대 4장이다(썸네일 제외).
- 이미지만으로 사실을 전하지 않는다. 이미지가 보여 주는 사실은 본문 문장에도 있어야 한다.
- 추론한 값을 시각 요소로 옮길 때는 본문과 같은 "우리 계산" 표기를 유지한다. 미발표 내용은 요점 상자의 미발표 형식(점선 테두리 등)으로 구분한다.
- 시각 요소를 넣어도 360·390·430px에서 가로 넘침 0, 글자 14px 이상을 지킨다.

## 7. 채널별 구현 대응표

공통 규칙은 위와 같고, 구현만 다르다. 한쪽 구현을 바꾸면 다른 쪽도 같은 결과가 나오는지 확인한다.

| 규칙 | 네이버 블로그 | 사이트 |

| 긴 구분선 | H2 앞에 `─`(U+2500) 19자 독립 문단, 글자 크기 16(36자는 모바일에서 두 줄로 접혀 2026-09-24 변경). `check_post.py`가 개수 대조 | 절 사이 전체 폭 선(가운데 ✧), CSS로 자동 |

### 아직 맞지 않는 부분 (2026-09-24)

- 사이트 한국어판은 "한 문단 한 문장"이 아니다. 빌드가 110자에서 나눈다.
  새 사이트 글은 원고부터 한 문단 한 문장으로 쓰고, 기존 글은 개정할 때 맞춘다.
- 사이트 캡처 이미지에는 원본 픽셀 대조 검사가 없다. 캡처를 넣을 때는 크롭 좌표를 기록한다.
- 사이트 썸네일·홈 배경은 2026-09-24 전부 블리자드 공식 이미지로 바꿨다(10장). 썸네일 아래와 홈 배경에 "© Blizzard Entertainment"와 출처 링크를 표시하고, `validate.mjs`가 출처 장부 해시·크레딧 누락을 막는다. 이전 AI 삽화는 `design/thumbnails/archive-ai-v1/`에 보존했다.
- 사이트 기존 글은 2026-09-24 시각 요소 개편 중이다(명세 `sites/wofwforever/content/work/visual-revamp/SPEC.md`). 표·막대·단계·요점 상자·본문 공식 이미지를 넣기 전의 글이 남아 있고, 개정할 때 6절 기준으로 맞춘다. 네이버 블로그는 막대 그래프·요점 상자 전용 형식이 아직 없다.
