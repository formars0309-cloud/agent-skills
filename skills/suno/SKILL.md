# Suno 게임 오디오

사용자는 Suno 구독자다. 구독 등급·모델·잔여량은 추정하지 않고 현재 화면에서 확인한다. 특정 게임이나 작업 폴더에 종속되지 않는다. 대화와 결과 기록은 한국어로, 소리 묘사는 필요에 따라 영어로 작성한다.

## 작업 범위와 실행

- 스킬 설치·조사·프롬프트 작성 요청만으로 생성하거나 다운로드 크레딧을 쓰지 않는다.
- 실제 제작 요청이면 기존 구독의 포함 크레딧 안에서 요청한 자산을 생성하고 필요한 결과를 내려받는다. 범위가 모호하면 자산별 첫 생성 1회로 시작한다. 첫 결과를 평가한 뒤 명확한 결함을 고치는 추가 생성은 자산별 1회까지 기본으로 허용하고, 사용자 지정 예산·횟수가 있으면 그것을 따른다. 평가가 불가능하면 자동 재생성하지 않는다.
- 추가 결제·구독 변경·크레딧 구매는 사용자가 직접 한다. 잔여량이나 차감량이 보이지 않으면 이를 보고하고 대량·반복 실행을 피한다. 실패 뒤 차감 여부를 확인하지 않은 채 Create를 다시 누르지 않는다.
- 로그인·OAuth·CAPTCHA가 필요하면 해당 화면을 준비하고 사용자가 직접 완료하도록 안내한다. 다른 브라우저로 조용히 바꾸지 않는다.
- 라이브러리 저장과 외부 공개는 구별한다. 공개 게시·공유는 사용자가 명시적으로 요청한 경우에만 실행한다. 업로드 음원은 사용자가 지정한 사용 권한 있는 자료만 쓴다.

## 제작 흐름

1. 요청과 현재 프로젝트에서 자산의 용도, 분위기, 길이, 반복 여부, 보컬 유무, 저장 위치를 파악한다. 빠진 경미한 조건은 합리적으로 정하고 알린다. BGM은 별도 요청이 없으면 무보컬로 만든다. 단순 효과음에 음악용 BPM·조성을 억지로 붙이지 않는다.
2. 브라우저를 열기 전에 [Aside 조작](references/aside-workflow.md)을 읽는다. Aside MCP REPL을 우선 사용하고, MCP가 없는 세션만 `aside repl`로 진행한다. 로그인 후 제작 화면·사용 가능 모델·현재 크레딧을 확인한다.
3. 종류별로 경로를 선택하고 [프롬프트 예시](references/game-audio-prompts.md) 중 필요한 것만 참고한다.
   - **BGM·완성된 음악:** Create의 Custom 음악 모드와 Instrumental 설정을 사용한다. 길이·BPM·루프 요구는 목표이며 결과 보장이 아니다.
   - **단발 효과음·짧은 징글:** Sounds → One Shot을 우선한다.
   - **환경음·반복 샘플:** Sounds → Loop를 우선한다. 음악 루프는 필요할 때 BPM·Key를 맞춘다.
   - 공식 문서의 경로와 화면이 다르면 현재 화면을 따른다. Sounds가 안 보이면 메뉴와 계정의 제공 기능을 확인하고 제한을 보고한다. 일반 음악 생성으로 조용히 대체하거나 다른 유료 서비스를 구매하지 않는다.
4. 입력값·모드·Instrumental 상태를 새 snapshot으로 확인한 뒤 생성한다. 완료 상태와 생성된 자산의 링크를 확인한다. 일시 지연에는 진행 상태를 확인하며 기다리고, 오류·장기 정체에는 생성 여부와 차감 여부부터 확인한다.
5. 후보를 실제 청취할 수 있는 도구로 비교한다. BGM은 보컬 혼입·장면 적합성·반복 피로, SFX는 타격 시점·불필요한 음악·잔향, 루프는 접합부·주기 변화를 확인한다. 재생 버튼 클릭만으로 청취했다고 말하지 않는다. 청취할 수 없으면 후보 링크를 제공하고 음질 평가는 미검증으로 남긴다.
6. 내려받기 전에 [공식 기능·이용 조건](references/suno-current-checks.md)으로 최신 다운로드 차감·상업 이용 조건을 확인한다. 후보 전부를 무조건 받지 말고 선택된 결과 위주로 받는다. WAV가 가능하면 편집 원본으로 우선하고, MP3만 제공되면 원래 형식을 보존한다. MP3를 WAV로 변환해 음질이 개선됐다고 설명하지 않는다.
7. 다운로드 파일의 존재·크기를 확인한다. 로컬 `ffprobe`가 있으면 실제 길이·코덱·샘플레이트·채널을 측정한다. 자산 적용에 필요한 경우에만 별도 파생본으로 트리밍·루프 접합·형식 변환을 수행하고 원본을 보존한다. 경로는 현재 프로젝트 또는 사용자가 지정한 곳을 쓰며, 없으면 작업 폴더의 `artifacts/suno/`를 쓴다.

## 결과 기록

다운로드와 함께 `suno-manifest.json` 또는 짧은 Markdown 기록을 남긴다. 기존 기록은 덮어쓰지 않고 자산별로 추가한다.

- 자산 ID·게임 내 용도·Suno 링크·생성/다운로드 일시
- 사용한 프롬프트·모드·모델·화면에서 확인한 설정
- 원본/파생 파일 경로·실측 길이·포맷, 수행한 편집
- 청취 여부·확인된 결함·루프 접합 검증 여부
- 확인 가능한 생성/다운로드 차감량, 당시 플랜 및 이용 조건 출처·확인일

관측하지 못한 값은 미확인으로 기록한다. 계정 이메일·결제 정보·쿠키·토큰·서명된 다운로드 URL은 기록하지 않는다. 최종 보고에는 파일/후보 링크, 실제 생성·다운로드 수, 검증 결과와 남은 제한을 짧게 남긴다.
