# 웹툰 표정 연출

웹툰 콘티·컷·컷씬 제작과 그림 수정에서는 별도의 표정 요청이 없어도 이 절차를 적용한다. 모든 등장인물에 각자의 감정·시선·반응을 설계하되, 문자 교정만 요청한 경우에는 원화를 재생성하지 않는다.

감정 이름만 지시하지 말고 **무슨 일을 알아차렸고, 감추거나 드러내려는 감정이 무엇이며, 어떤 얼굴·몸의 변화로 읽힐지**를 정한다. 표정의 다양성보다 상황과 인물에 맞는 반응을 우선한다.

이 스킬은 공식 웹툰 일부 장면을 관찰해 만든 연출 지식과 제작 절차다. 모델 재학습·작품 전편 분석·작화 품질 보장을 뜻하지 않는다. 관찰 범위와 출처는 [관찰 기록](references/observations.md)에 있다. 작가 의도를 사실로 단정하거나 댓글을 시각 근거로 삼지 않는다.

## 작업 시작

1. 현재 작품의 AGENTS.md, 최신 인계, 캐릭터 고정 기준, 사용자가 선택한 실제 이미지, 해당 장면의 앞뒤 콘티를 읽는다. 오래된 시트와 최신 원고가 충돌하면 최신 사용자 수정과 인계를 따른다.
2. 우리 캐릭터의 **변하지 않는 요소**(얼굴 골격·연령 인상·눈 색·헤어·기호·체형·복장)와 **움직일 요소**(눈꺼풀·눈썹·시선·입·턱·목·어깨)를 나눈다. 홍조·땀·효과선은 필요할 때 붙이는 보조 신호다.
3. 요청이 콘티이면 감정 설계와 지시문까지, 제작이면 실제 이미지 생성과 시각 대조까지, 검수이면 기존 이미지의 문제와 최소 수정안까지 수행한다. 프로젝트의 제작 관리 도구가 있으면 그 기록에 연결하되 임의로 승인 상태를 바꾸지 않는다.

## 컷별 연기 설계

[연출 사전](references/direction.md)을 읽고 아래 정보를 짧게 작성한다. 이미 정해진 콘티의 사건·대사는 표정 작업을 이유로 바꾸지 않는다.

| 항목 | 기록할 내용 |
|---|---|
| 사건·목표 | 지금 알아차린 사실 / 상대에게 보이고 싶은 태도 |
| 감정·강도 | 주감정 하나, 필요하면 숨기는 감정 하나. 강도 0~4는 제작용 상대 척도 |
| 얼굴 | 눈썹 안쪽/바깥쪽, 눈꺼풀, 시선, 입 모양을 모순 없이 구체화 |
| 몸·시선 대상 | 목·어깨·손의 한 가지 주요 반응, 인물 본인 기준 좌우 |
| 컷 역할 | 준비 / 인지 / 반응 / 여운 중 장면에 맞는 역할 |
| 이전 컷과 차이 | 눈·입·자세·구도 가운데 독자가 알아볼 변화 |
| 보존·제한 | 실제 참조 경로, 외형 고정 요소, 홍조·효과 사용 여부 |

감정 강도와 그림의 변형량은 별개다. 강한 절망을 조용한 표정으로 보일 수 있다. 효과선과 큰 입을 모든 강한 감정에 붙이지 않는다. 같은 표정 유지가 침묵·긴장·반복 개그에 필요하면 이유를 기록하고 유지한다.

## 생성에 전달

실제 캐릭터 이미지를 먼저 열어 확인한 뒤 생성 도구의 이미지 참조로 전달한다. 텍스트에 경로만 적은 것은 이미지 첨부가 아니다. 입력 이미지는 캐릭터 기준 / 수정 대상 / 장면 참고처럼 역할을 명시한다.

생성 지시문은 `한 컷의 사건 → 우리 캐릭터 참조 → 얼굴 변화 → 몸·시선 → 구도 → 보존할 요소 → 대사·레터링` 순으로 작성한다. 작품명 대신 관찰에서 추출한 조형 동작을 적는다. 원작 인물·의상·고유 컷을 우리 캐릭터 설정으로 가져오지 않는다.

실제 제작 요청이면 사용 가능한 이미지 생성 도구를 사용하고, 한 이미지에 한 컷을 생성한다. 다중 컷을 만들어 잘라 쓰지 않는다. 원본과 프롬프트를 보존하고 프로젝트 납품 규격으로 변환한다. [적용 예시](references/application.md)는 고정 프롬프트가 아닌 출발점이다.

## 검수와 교정

생성 결과를 실제로 열어 다음을 판단한다. 자동 검사만으로 감정 전달을 통과시키지 않는다.

- 대사를 잠시 가리고 보았을 때 목표 감정 또는 의도한 태도가 읽히는가? 다른 감정으로도 읽히면 그 모호함이 장면에 맞는가?
- 기준 인물과 같은 얼굴·연령·기호인가? 놀람을 눈 확대와 아기 얼굴로 혼동하지 않았는가?
- 눈썹·눈·입과 몸의 방향이 함께 작동하는가? 의도한 감정 은폐 외에는 서로 상충하지 않는가?
- 앞뒤 컷을 나란히 보았을 때 감정 변화와 시선의 대상이 읽히는가? 같은 기본 미소나 찌푸림으로 눌리지 않았는가?
- 최종 납품 폭과 모바일 축소에서 핵심 눈·입 모양이 보이는가? 글자·머리카락·효과가 가리지 않는가?

문제가 있으면 가장 큰 원인 하나(예: 웃는 입 때문에 놀람이 기쁨으로 읽힘)를 특정해 해당 부위를 수정한다. 바뀌지 않아야 할 요소를 다시 적는다. 반복 실패 시 표정 세부를 계속 늘리지 말고 구도·크기·가림을 바꾸는 안을 검토한다.

결과에는 실제 관찰 범위, 적용 규칙, 저장 경로, 시각 검수 결과와 남은 한계를 남긴다. 새로운 관찰을 추가할 때는 URL·회차·장면 위치·눈으로 본 사실·해석·적용을 분리한다. 검증되지 않은 응용을 원작에서 확인한 사실처럼 기록하지 않는다.
