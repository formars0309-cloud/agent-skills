# 정본·서사·연속성 선별 적용 v1

2026-09-16 사용자 승인: ORCA 웹툰 제작 전역 규칙 v1.0 중 정본 구분·인물별 지식·회차 변화·복선·오류 우선순위를 기존 제작 절차에 보완한다. 이 파일이 공용 정본이며 작품 설정은 각 작품 `production/서사관리.md`에서 읽는다.

## 범위와 작업 시작

- 기존 AGENTS → production/README.md → 작품별 서사관리.md → 실제 상태·설정·직전 원고 순으로 필요한 자료를 읽는다. 작품별 최신 사용자 지시가 우선이다.
- `production/story-policy.json`이 있는 작품의 지정 회차부터 신규 `init`에 적용한다. 기존 회차의 검수·승인을 소급 생성하거나 공개 원고를 재제작하지 않는다. 기존 파일 수정 요청에는 관련된 서사 오류만 확인한다.
- 이미 위임받은 기획·제작·수정 범위에서는 진행한다. 대본·콘티 단계마다 확인 질문을 추가하지 않는다. 작업 허가, AI 검수 통과, 사용자의 특정 버전 승인, 실제 공개를 별개로 기록한다. 사용자 승인이 없는 것을 LOCKED로 바꾸지 않는다.
- 3컷·수정1회 제한, 결말 선확정, 별도 장부 대량 생성, 식자 방식 일괄 전환은 도입하지 않는다. 실제 작업 범위와 작품별 제작 방식을 따른다.

## 기존 관리 파일 안의 최소 기록

신규 관리 파일은 `brief.story`에 다음 7개 문자열을 갖는다. 각 항목은 한두 문장이나 필요한 표·파일 링크로 충분하다. 별도 내용 정본이 있으면 경로·절·버전을 정확히 연결하고 다시 복사하지 않는다. 의도적으로 해당 내용이 없으면 ‘없음: 이유’를 적으며, 알 수 없는 것은 OPEN과 영향을 적는다.

| 필드 | 기록할 것 |
|---|---|
| canon | 이번 회차가 사용하는 설정의 LOCKED(사용자 승인/실제 공개 근거), PROPOSED(제안), OPEN(미정), 대상 파일·버전·근거 위치. 문서 제목이 ‘공식’이라는 이유로 전체 승인하지 않는다. |
| start_state | 시작 시점의 시간·장소·관계·필요한 의상/소품 상태와 실제 근거. 직전 회차가 미승인이면 가정 분기라고 표시한다. |
| knowledge | 실제 진실 / 독자가 아는 것 / 인물별로 아는 것 / 각자의 오해. 이번 사건에 필요한 차이만 적고 인물의 거짓말을 세계관 진실로 옮기지 않는다. |
| end_state | 이번 화의 선택·반응→결과→감정/관계/정보 변화와 독자 보상. 제작 중에는 변경 제안이며, 승인 근거 확인 후 기존 정본 상태에 반영한다. |
| foreshadowing | 사용하는 단서 ID, 계획 위치와 실제 공개 위치·버전의 구분, 회수 조건·위치와 상태. 회차 안에서 회수되는 개그도 충분하며 모든 대사를 복선으로 만들지 않는다. |
| authority | 이번 제작의 실제 사용자 요청과 범위, 특정 버전 승인 근거, 미확인 승인. 위임은 실제 요청을 요약하고 승인을 꾸며 쓰지 않는다. |
| review_note | 검토한 컷·대사와 P0/P1/P2, 해결 내역·남은 문제. 미확인 검사는 미실시로 적는다. 단순 ‘통과’로 근거를 대신하지 않는다. |

예: ‘knowledge: 독자는 A가 쪽지를 쓴 것을 02컷에서 보지만 B는 08컷 전까지 모른다. B가 05컷에서 발신자를 단정하지 않도록 확인.’ 실제 내용은 해당 작품 원고에서 작성한다.

`check/review`는 이 7개 기록의 공백을 검사하고, 변경되면 기존 기획·콘티·컷 검수 해시를 무효화한다. 문자열이 채워졌다는 것은 서사 품질·승인 근거·오류 해결의 자동 판정이 아니다. 검수자는 원문을 대조해야 한다. 기록 누락을 피하려고 `brief.story`를 삭제하거나 구형 파일 복사로 신규 절차를 건너뛰지 않는다.

## 검수와 확정 반영

- **P0:** 핵심 정본 모순, 주요 컷/발화자 오류, 의도하지 않은 핵심 스포일러. 해결 전 완료 처리하지 않는다.
- **P1:** 읽기 순서·감정·표정·연속성을 방해하는 오류. 납품 전 수정하거나 실제 사용자 예외 판단과 적용 범위를 기록한다.
- **P2:** 취향·선택적 개선. 제안으로 남기며 자동 재작화하지 않는다.
- 기존 대사의 역할, 표정 스킬, 해부학적 좌우, 고정 레터링, 실제 참조 첨부, 한 이미지 한 컷, 690px JPEG·390px 판독·실제 여백 규칙을 유지한다. 새 서사 기록이 이미지 검수를 대신하지 않는다.
- 기획·콘티 검수 때 `review_note`의 미해결 P0/P1을 확인하고, 컷의 실제 시각 검수 근거는 기존 `reviews[].note`에 기록한다. 후반에 새 공통 서사 문제가 발견되면 기록을 갱신하고 영향받는 검수를 다시 수행한다.
- 승인된 원고와 end_state를 대조한 후 기존 상태 문서의 해당 항목만 갱신한다. 초안의 사건을 공개된 사실로 올리지 않는다. 숨은 설정은 프롬프트·홍보물에 통째로 복사하지 않는다.

## 측정과 구회차 보호

`schedule.story_metrics`는 실제 측정한 대본 이후 서사 수정 컷수, 채택 컷당 생성/수정 호출수, 재개·문서관리 시간(분), 불필요한 승인 질문 횟수다. 미측정은 null이며 값 변경은 이미지 검수를 무효화하지 않는다. 각 작품 신규1회차에서 부담과 효과를 비교하고 난이도 차이를 고려한다.

새 정책 파일은 `init`만 읽는다. 기존 관리 파일·project.json·AGENTS.md를 일괄 수정하지 않는다. 신규 파일에만 작품별 서사관리.md를 references로 추가한다. 이후 이 안내의 실제 변경은 해당 신규 회차의 재검수가 필요할 수 있으므로 작업 중인 안내를 습관적으로 갱신하지 않는다.
