# uu — 모르는 줄도 모르는 것 찾기

체크리스트는 이미 아는 질문(known unknowns)만 다룬다. 이 스킬은 **질문 목록에 아예 없던 것**을 끌어낸다.
모르는 줄도 모르는 것은 두 종류다.

| 모드 | 무엇을 찾나 | 언제 | 결과 |
|---|---|---|---|
| **A. 위험 점검** | 모르고 있다가 터지는 것 | 만든 뒤, 배포·발행 직전 | 처리된 위험 목록 |
| **B. 지식 추천** | 몰라서 못 쓰고 있는 개념·방법·도구 | 기획·계획 단계, 막혔을 때 | 적용법과 첫 실험이 붙은 개념 카드 |

요청이 "놓친 위험", "괜찮을까", "배포 전"이면 A, "알면 좋은 것", "기획", "방법", "개념"이면 B를 쓴다. 새 프로젝트 기획이면 B를 먼저 하고 A의 1~4단계를 이어서 한다. 애매하면 둘 다 가볍게 한다.

# 모드 A. 위험 점검

목표는 걱정 목록이 아니라 **처리된 목록**이다. 찾은 항목은 모두 확인·가드레일·감지·수용 중 하나로 끝낸다.

## A. 언제 쓰나

- AI가 대부분 짠 코드를 실제로 쓰거나 배포하기 전
- 처음 쓰는 플랫폼·API·결제·인증·자동 예약을 붙일 때
- 발행·배포·삭제·대량 작업처럼 되돌리기 어려운 동작 직전
- 사고가 난 뒤: "이건 왜 아무도 안 물어봤지?"를 따질 때

사소한 수정이나 한 번 쓰고 버릴 스크립트에는 쓰지 않는다. 비용 대비 효과가 없다.

## A. 절차

### 1. 대상과 판돈 정하기 (1분)

- 무엇을 점검하나: 저장소·기능·자동화·글 한 편 등 범위를 한 줄로 적는다.
- 틀리면 무엇을 잃나: 돈, 데이터, 계정, 평판, 시간 중 무엇인지. 판돈이 작으면 3단계까지만 한다.

### 2. 네 칸 채우기

| 칸 | 적을 것 |
|---|---|
| 아는 것 | 확인된 사실. 근거(파일·명령 결과·문서)를 함께 적는다 |
| 모르는 줄 아는 것 | 열린 질문. 이미 조사할 수 있는 것 |
| 알면서 무시한 것 | 암묵적 가정. "당연히 ~겠지"로 시작하는 문장을 전부 적는다 |
| 모르는 줄도 모르는 것 | 3~5단계로 채운다. 처음엔 비어 있는 게 정상이다 |

**가정 적기가 가장 효과가 크다.** "사용자는 나 혼자", "이 API는 무료", "파일은 항상 있다", "로그인은 유지된다", "시간대는 한국" 같은 문장이 사고의 씨앗이다.

### 3. 영역 훑기

아래 영역을 하나씩 대상에 대입해 "여기서 뭐가 잘못될 수 있나"를 묻는다. 해당 없는 영역은 이유를 한 줄 남기고 넘긴다.

| 영역 | 대표 질문 |
|---|---|
| 비밀·보안 | 키·토큰·개인정보가 코드·로그·커밋·공개 URL에 들어가나? 인증 없이 열리는 경로가 있나? 입력값을 믿나? |
| 돈 | 유료 API를 반복·무한 호출할 수 있나? 요금 상한·알림이 있나? 자동 결제·구독이 걸리나? |
| 데이터 | 덮어쓰기·삭제가 되돌려지나? 백업이 실제로 복원되나? 동시에 두 곳이 같은 파일을 쓰나? |
| 규모·시간 | 데이터·사용자가 10배, 100배면? 오래 돌면 쌓이는 것(로그·캐시·임시 파일)은? 타임아웃·재시도 폭주는? |
| 외부 의존 | 상대 서비스가 바뀌거나 막히면(요청 제한·약관·로그인 만료·UI 변경)? 버전 고정은? |
| 환경 | 다른 기기·OS·시간대·인코딩·경로(한글·공백)에서도 되나? 로컬에서만 되는 건 아닌가? |
| 자동화·예약 | 사람이 안 볼 때 실패하면 누가 아나? 중복 실행되면? 중지 방법이 있나? |
| 사람·운영 | 다른 에이전트나 세션이 같은 걸 만지나? 6개월 뒤 내가 이걸 이해하나? 문서가 있나? |
| 법·정책 | 개인정보, 저작권·이미지 출처, 플랫폼 정책, 의료·금융 표현 규제에 걸리나? |
| 사실·내용 | 글이라면: 원문 대조 없이 옮긴 수치·인용이 있나? 추정이 단정으로 바뀌었나? |

### 4. 사전 부검 (pre-mortem)

"3개월 뒤 이게 크게 실패했다. 원인은 무엇이었나?"를 가정하고 **서로 다른 실패 이야기 5개**를 쓴다.
각 이야기는 구체적인 사건 하나로 쓴다. 예: "무료 한도를 넘긴 뒤 재시도 루프가 밤새 돌아 40만 원이 청구됐다."
3단계 영역표에 없던 이야기가 나오면 그게 이번 점검의 수확이다.

### 5. 바깥 눈 빌리기

같은 모델은 같은 사각지대를 공유한다. 판돈이 크면 적어도 하나는 한다.

- **교차 모델**: `현자` 스킬로 "이 작업에서 내가 묻지 않았지만 물었어야 할 질문 10개"를 던진다. 네 답에서 겹치지 않는 항목을 본다.
- **실측**: 추측 대신 실제로 돌려 본다. 빈 입력, 아주 큰 입력, 네트워크 끊김, 로그인 만료, 두 번 실행, 다른 폴더에서 실행 등을 시험한다.
- **기록 뒤지기**: 같은 도구·플랫폼에서 난 과거 사고(메모리, Git 이력, 이슈, 공식 문서의 "알려진 문제")를 찾는다.

코드라면 최소한 아래는 실제로 돌린다.

```bash
git ls-files | grep -iE '\.env|secret|credential|\.pem|\.key|token' # 추적 중인 비밀 파일
git grep -nE '(api[_-]?key|secret|token|password)\s*[:=]\s*["'"'"'][^"'"'"']{8,}' # 코드에 박힌 값
git log --all --oneline -- '*.env' | head            # 과거에 커밋된 적 있나
```

값은 출력하지 않는다. 파일 이름과 줄 번호만 본다.

### 6. 처리하기

찾은 항목마다 하나를 고른다. "주의한다"는 처리가 아니다.

| 처리 | 뜻 | 예 |
|---|---|---|
| 확인 | 사실 여부를 지금 검증해 아는 것으로 바꾼다 | 요금표 확인, 복원 테스트 |
| 가드레일 | 일어나도 피해가 작게 막는다 | 요금 상한, 백업, 드라이런, 확인 단계, 잠금 파일 |
| 감지 | 일어나면 바로 알게 한다 | 실패 알림, 로그, 일일 보고서 항목 |
| 수용 | 알고도 감수한다. 이유를 적는다 | "혼자 쓰는 도구라 동시성은 무시" |

사용자 전역 규칙에 따라 되돌릴 수 있는 처리(확인·가드레일·감지 추가)는 바로 적용한다. 결제·권한·삭제·공개 발행이 걸린 처리는 준비만 하고 사용자에게 넘긴다.

### 7. 다음부터 아는 것으로 남기기

이번에 드러난 항목 중 **다른 작업에서도 반복될 것**은 흔적을 남긴다. 그래야 다음엔 unknown unknown이 아니다.

- 그 프로젝트에만 해당: 프로젝트 `AGENTS.md`나 체크리스트에 한 줄 추가
- 여러 프로젝트에 해당: 해당 전역 스킬에 추가하거나, 이 스킬의 3단계 영역표에 질문을 추가
- 사고가 실제로 났으면: 날짜·원인·막은 방법을 메모리에 남긴다

## A. 보고 형식

```
## uu 점검 — <대상> (<날짜>)
판돈: <잃을 수 있는 것>

### 드러난 항목
| # | 항목 | 어떻게 찾았나 | 처리 | 상태 |
|---|---|---|---|---|
| 1 | 재시도 루프에 상한 없음 | 사전 부검 | 가드레일: 최대 3회 | 적용함 |
| 2 | 로그인 만료 시 조용히 실패 | 실측 | 감지: 보고서에 표시 | 적용함 |
| 3 | 동시 실행 | 영역 훑기 | 수용: 혼자 씀 | — |

### 가정 목록
- ...

### 사용자 몫
- <결제·권한·삭제·발행이 걸려 사용자가 결정할 것>

### 남긴 흔적
- <추가한 규칙·체크리스트·메모리>
```

## A. 하지 말 것

- 영역표를 기계적으로 채우고 "해당 없음" 도장만 찍기. 한 영역이라도 실제로 실행·확인한 게 있어야 한다.
- 막연한 걱정 나열. 구체적인 사건으로 쓰지 못하면 아직 항목이 아니다.
- 모든 위험 없애기. 판돈에 비해 과한 가드레일은 그 자체로 새 위험(복잡성)이다.
- 찾은 것을 보고만 하고 끝내기. 처리 칸이 빈 항목은 남기지 않는다.

# 모드 B. 지식 추천

사람은 이름을 모르는 개념을 검색할 수 없다. "A/B 테스트"라는 말을 모르면 제목 두 개를 비교해 볼 생각을 못 하고, "코호트"를 모르면 재방문을 잴 생각을 못 한다.
이 모드는 **그 분야 전문가가 이 프로젝트를 봤다면 가장 먼저 꺼냈을 개념**을 찾아 바로 써먹을 수 있는 형태로 건넨다.

목표는 공부 목록이 아니라 **써먹을 목록**이다. 개념마다 이 프로젝트에 적용하는 방법과 첫 실험을 붙인다.

## B. 절차

### 1. 프로젝트와 현재 방식 파악

- 목표(무엇을 얻으려 하나), 현재 방식, 막힌 곳, 쓸 수 있는 자원(시간·돈·도구)을 적는다.
- 추측하지 말고 먼저 읽는다: 프로젝트 `AGENTS.md`·README·계획 문서, 메모리, 최근 Git 이력.
- 사용자가 이미 쓰는 용어를 모은다. 이게 "이미 아는 것" 목록이 된다.

### 2. 이 문제를 직업으로 푸는 사람들 떠올리기

같은 문제를 매일 푸는 **직군 4~6개**를 고른다. 사용자와 가까운 분야와 먼 분야를 섞는다.

예: 게임 정보 블로그라면 SEO 담당자, 잡지 편집자, 데이터 분석가, 커뮤니티 매니저, 도서관 사서(분류·색인), 게임 기획자.

먼 분야에서 좋은 개념이 자주 나온다. 가까운 분야만 고르면 이미 아는 것만 나온다.

### 3. 직군별 개념 뽑기

직군마다 "이 사람이 우리 작업을 보면 먼저 꺼낼 말"을 3~5개 뽑는다. 개념, 방법론, 지표, 도구, 흔한 실수 모두 된다.
판돈이 크거나 처음 가는 분야면 `현자`로 여러 모델에 같은 질문을 던진다.

> "<프로젝트 한 줄 설명>. 현재 방식: <…>. 이 분야 전문가라면 당연히 쓰지만 초보자는 이름조차 모를 개념·방법·도구 10개를 알려줘. 각각 한 줄 뜻과 이 프로젝트에 쓰는 법."

### 4. 거르기

후보를 아래 순서로 걸러 7개 이하만 남긴다. 30개를 던지면 아무것도 안 쓴다.

1. **이미 아는 것 빼기**: 1단계 용어 목록과 저장소·메모리에서 그 용어(한글·영문)를 검색한다. 이미 쓰고 있으면 뺀다. 이름만 모르고 이미 하고 있는 것은 따로 표시한다. 이름을 알면 더 찾아볼 수 있으니 가치가 있다.
2. **이 프로젝트에 붙는가**: 적용 방법을 한 문장으로 못 쓰면 뺀다.
3. **효과 대비 학습 비용**: 한 시간 안에 첫 실험이 가능한 것을 우선한다. 큰 개념은 "알아만 두기"로 보낸다.
4. **사실 확인**: 정의·수치·도구 이름을 공식 문서나 신뢰할 출처로 확인한다. 링크를 붙이면 열어서 실제로 있는지 확인한다. 확인 못 한 것은 "미확인"으로 표시한다.

### 5. 개념 카드 만들기

```
### <개념 이름> (<원어>)
- 한 줄 뜻: <전문 용어 없이>
- 어느 직군이 쓰나: <직군>
- 왜 이 프로젝트에: <현재 방식의 어떤 빈틈을 메우나>
- 적용 예: <이 프로젝트의 실제 파일·글·작업에 대입한 예>
- 첫 실험: <1시간 안에 해볼 수 있는 것, 성공 기준>
- 더 볼 곳: <확인한 출처 1~2개>
- 이미 비슷하게 하고 있나: <예/아니오 — 예라면 어디서>
```

### 6. 지도로 묶기

| 칸 | 뜻 |
|---|---|
| 지금 바로 | 첫 실험이 쉽고 효과가 큰 것. 2~3개 |
| 다음 단계 | 지금 것이 자리 잡은 뒤 |
| 알아만 두기 | 당장은 과하지만 이름은 알아둘 가치가 있는 것 |

추천한 개념끼리 관계가 있으면 한 줄로 잇는다. 예: "검색 의도를 알아야 제목 A/B 테스트의 가설을 세울 수 있다."

### 7. 남기기

- 사용자가 채택한 개념은 프로젝트 계획 문서나 `AGENTS.md`에 한 줄로 남긴다. 어떤 실험으로 쓰기로 했는지까지 적는다.
- 사용자가 원하면 첫 실험을 바로 진행한다. 되돌릴 수 있는 범위에서만 한다.

## B. 보고 형식

```
## uu 지식 추천 — <프로젝트> (<날짜>)
목표: <…> / 현재 방식: <…> / 막힌 곳: <…>
살펴본 직군: <직군 목록>

### 지금 바로
<카드 2~3개>

### 다음 단계
<카드>

### 알아만 두기
- <이름> — <한 줄>

### 이미 하고 있던 것 (이름만 몰랐던 것)
- <이름> — <어디서 하고 있나>
```

## B. 하지 말 것

- 교과서 목차 나열. "마케팅 기초", "데이터 분석"처럼 넓은 말은 개념이 아니다.
- 적용 예를 일반론으로 쓰기. 이 프로젝트의 실제 글·파일·작업에 대입해야 한다.
- 확인하지 않은 수치·출처 붙이기. "연구에 따르면" 같은 말은 출처를 확인하지 못하면 쓰지 않는다.
- 사용자가 이미 잘 쓰는 개념을 새것처럼 추천하기. 1단계 용어 목록을 반드시 거친다.
