# 단계별 산출물 계약

각 단계의 주체는 SKILL.md의 교차 검수 표를 따른다. 1단계에 실제 메인 작성자·작성 참여 에이전트·검수 에이전트를 기록한다. 아래 기존 모델명·파일명은 과거 양식 호환 표기이며 실제 수행 주체를 고정하지 않는다. 필수 근거·감사·실행 증거 항목은 유지하고 실제 모델명을 기록한다.

## `01-question-and-evidence.md`

- 작업 정보: 제목, slug, 대상 독자, 확인 기준일
- blueocean 실측 실행일·명령·키워드·결과 JSON 경로·수요/공급/상업성/추세·채택/제외 이유
- 대표 상황과 검색 의도
- `readerQuestion`, `addedValue`, `decision` 후보
- 원천 우위 테스트와 판정
- 포함 범위와 제외 범위
- 의료·제도 경계
- 형제 원고 중복 점검
- 잠정 결론과 결론 변경 조건
- 권장 구조
- 주장별 근거표
- 미정·상충·보류 목록
- 2단계 진행 여부

## `02-evidence-bound-draft.md`

- 작성 주체와 실행 기록
- 제목 후보와 `quickAnswer`
- 첫 문단이 결론인 완결된 전체 초안
- 사실 문장과 근거 ID 연결
- 필요한 표·질문 목록
- 근거표 밖이라 쓰지 않은 내용
- 추가 확인 항목

## `03-source-trace-audit.md`

- 새 터미널·새 세션의 감사 주체와 원천 확인 방식
- 터미널·세션/실행 ID, CLI 버전, 시작·종료 시각, 입력 SHA-256, 프롬프트·원출력 경로, 종료 코드 및 입력 SHA 재대조
- 원천 대조 감사 범위
- `미추적 / 불일치 / 과대` 건수
- 번호형 지적표(심각도 `차단/필수 수정/권고`, 종류 `내용/기계 대조`, 원천 근거, 독자 영향)
- 추적 확인표
- 검수 회차 이력(회차·실행 폴더·판정·종결 방식). 상한 최초 1회 + 재검수 2회
- 4단계 전달 과제
- 판정: `통과 / 수정 후 확인 / 반려 / 실행 보류`. 파일 최종 판정이 `통과`가 되려면 마지막 실행기 기록이 `통과`이거나 기계 대조 종결(`confirmed`)이어야 한다

이 파일에는 수정된 원고를 넣지 않는다. 상한 소진 시 `audits/stage3-hold.md`를 연결하고 판정은 `반려` 또는 `실행 보류`로 둔다.

## `04-improved-draft.md`

- 개선 주체와 실행 기록
- 개선된 완결 원고 전체
- 3단계 과제 반영표
- `반영 / 부분 반영 / 미반영` 이유
- 새로 확인한 원천과 남은 위험

## `05-final-edited.md`

- 확정 제목과 `quickAnswer`
- 완결된 전체 본문
- 보호자 언어 편집 판단
- 삭제·통합한 문단
- 표·목록의 모바일 흐름
- 6단계 집중 위험

편집 메모만 두지 않는다. 이 파일만 읽어도 전체 원고를 감사할 수 있어야 한다.

## `06-prepublish-audit.md`

- 사실 감사 주체·방식·지적표·판정
- 가치·밀도 감사 주체·방식·지적표·판정
- 사실·가치 감사 각각 별도 새 터미널·새 세션의 실제 실행 기록(3단계와 동일 항목), 미실행이면 전체 보류
- 재검증과 `반영 / 기각 / 보류` 판정표(지적마다 심각도·종류)
- 검수 회차 이력(감사별 회차·실행 폴더·판정·종결 방식)과 상한 소진 시 보류 반환 연결
- 출처 링크·적용일·환경 확인
- 형제 원고 자기잠식 확인
- 근거 미확보로 뺀 내용
- 자동 감사 최종 판정: `통과 / 반려 / 보류`. 사실·가치 각각 실행기 기록이 `통과` 또는 `confirmed`이고 검수한 원고 SHA가 현재 정본과 같아야 `통과`
- 의료인 승인: 기본 `대기`
- 공개 승인: 기본 `대기`

## 7단계 `src/content/guides/<slug>.md`

- 현재 Astro 스키마를 만족하는 프론트매터
- 6단계에서 확정한 수정까지 반영한 본문
- 실제 원문 URL과 확인일
- 작업용 근거 ID 제거
- 의료인 승인 전 `draft: true`

사이트 정본은 이 파일 하나다. `content-work`에 같은 최종본을 추가로 만들지 않는다.
