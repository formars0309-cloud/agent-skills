# 감사·승인 규칙

## 작성자에 따른 교차 검수 — 2026-09-07 사용자 지정

사용자가 글쓰기를 지시한 현재 에이전트가 메인 작성자다. Claude Code와 Codex 모두 동등하게 시작할 수 있으며, 다른 쪽 세션의 존재 여부를 조건으로 삼거나 별도 인계 승인을 요구하지 않는다. 1단계에 실제 `메인 작성자`, `작성 참여 에이전트`, `검수 에이전트`와 역할별 터미널/세션을 기록한다.

| 메인 작성자 | 3단계 초안 감사 | 6단계 최종 내용 검수 | 별도 최종 검토가 있는 경우(내차공략 7단계) |
|---|---|---|---|
| Codex | 새 Claude Code 세션 | 또 다른 새 Claude Code 세션 | 또 다른 새 Claude Code 세션 |
| Claude Code | 새 Codex 세션 | 또 다른 새 Codex 세션 | 또 다른 새 Codex 세션 |

‘다른 에이전트’는 같은 모델의 다른 세션만을 뜻하지 않는다. 해당 원고의 기획·초안·개선·편집에 참여하지 않은 반대쪽 에이전트 제품(Codex ↔ Claude Code)을 사용한다. 작성은 한쪽이 맡고 검수자는 원고를 수정하지 않는다. 검수 의견을 받은 작성자가 원천을 대조해 수정하는 것은 허용한다. 양쪽 모두 작성에 참여한 경우 그 사실을 보존하고 독립 검수자를 확보할 때까지 보류한다. 작성자를 바꿔 기록하거나 참여 이력을 지우지 않는다.

모든 감사·검수·재검토는 매번 새 Orca 터미널의 새 세션에서 수행한다. 기존 세션 재사용, resume/continue, 대화 이력·요약·자기평가·통과 예상·이전 감사 판정 전달은 금지한다. 보호자 노트 6단계의 사실 감사와 가치·밀도 감사도 반대쪽 에이전트를 사용하되 각각 별도 새 터미널·새 세션을 연다. 이전 검수만 수행했고 작성하지 않은 같은 제품은 다음 검수에도 사용할 수 있지만 세션은 새로 만든다.

검수자에게는 해당 단계 원고, 독자 질문·범위, 공식 근거·계산 명세와 검수 기준만 제공한다. 필요한 원문 조회·실제 브라우저 관측·자동 검사는 허용하되 원고 쓰기는 금지한다. 3단계는 초안, 6단계는 최종 편집 후보, 별도 최종 검토는 사이트 정본을 대상으로 한다. 모델 선택과 무관하게 기존 사실·계산·가치·모바일·해시·실행 증거·승인 기준을 유지한다. 검사 통과를 위해 실제 실행 주체와 다른 모델명을 기록하지 않는다.

반대쪽 CLI·인증을 사용할 수 없으면 작성과 근거 정리까지 진행하고 해당 검수는 보류한다. 같은 작성 에이전트의 새 세션이나 자체 검수로 대체하지 않는다. 이 규칙은 이번 작성 중 원고부터 적용하며 과거 실행 기록은 보존한다.

## 필수 독립 실행

3단계 초안 감사와 6단계 최종 내용 검수는 각각 반드시 새 Orca 터미널에서 이전 대화를 받지 않는 새 세션으로 실행한다. 기존 터미널·세션 재사용, resume/continue, 작성 대화의 요약·자기평가·통과 예상 전달은 금지한다. 같은 대화에서 분기한 서브에이전트는 새 터미널 검수를 대체하지 못한다. 검수자는 원고를 수정하지 않고 지적과 판정만 반환하며, 작성자가 공식 원천으로 재확인해 수정한다. 수정본 재검수도 또 다른 새 터미널·새 세션에서 수행한다.

6단계 사실 감사와 가치·밀도 감사도 서로 별도의 새 터미널·새 세션으로 진행한다. 3단계에는 초안과 질문·범위·근거표, 6단계에는 최종 편집본과 질문·범위·근거표를 제공한다. 가치 감사에만 필요한 공개 형제 원고를 추가한다. 작성자의 잠정 결론·자기평가·과거 판정은 제외하고 감사 기준과 원천 위치를 함께 준다.

## 감사자는 원고를 수정하지 않는다

감사 단계에서 문장을 고치면 문제와 수정의 경계가 사라진다. 감사자는 원고 위치를 인용하고 판정과 번호형 과제만 남긴다. 수정은 다음 개선 단계에서 수행한다.

## 사실 감사

초안보다 원천을 먼저 읽는다. 다음 주장을 모두 뽑는다.

- 금액, 비율, 기간, 횟수, 인원, 연도, 기준값
- 대상 요건, 신청 주체, 서류, 절차, 기한
- 법령·고시·기관·지침 이름과 적용 범위
- 원인과 결과를 잇는 문장
- `대부분`, `보통`, `가장`, `자동으로` 같은 일반화
- 치료가 계속되거나 중단된다고 읽힐 수 있는 문장

각 주장을 다음 중 하나로 판정한다.

| 판정 | 의미 |
|---|---|
| 추적됨 | 현재 원천의 정확한 위치와 짧은 대조를 제시할 수 있음 |
| 미추적 | 제공된 원천 어디에도 근거가 없음 |
| 불일치 | 값·대상·조건·시점이 원천과 다름 |
| 과대 | 조건부 원천을 절대적·일반적 문장으로 넓힘 |

`미추적`, `불일치`, `과대`는 각각 아래 심각도 규칙으로 판정한다. 독자의 판단·안전·자격·금액·기한을 바꾸는 미추적·불일치·과대는 `차단`이고 하나라도 있으면 반려다. 근거표 행 번호·위치 표기·메타데이터처럼 원고의 의미를 바꾸지 않는 불일치는 `필수 수정`(기계 대조)이며 반려가 아니라 `수정 후 확인`이다. 출처 링크가 달렸다는 이유만으로 통과시키지 않는다.

## 가치·밀도 감사

다섯 항목을 따로 판정한다.

1. **원천 우위**: 선언한 `addedValue`가 본문 전체에서 이행됐는가.
2. **질문 정렬**: `readerQuestion`과 실제 본문이 같은 질문에 답하는가.
3. **결정 가능성**: 독자가 무엇을 확인하거나 물을 수 있게 되는가.
4. **문단 삭제 테스트**: 지워도 정보 손실이 없는 문단이 남았는가.
5. **자기잠식**: 기존 공개 글과 같은 질문·결정을 반복하지 않는가.

1~4 중 하나라도 `차단`(원천 우위 미이행, 질문 불일치, 결정 불가)이면 전체 반려다. 문단 삭제 테스트의 잉여 문단, 문체·구성 선호, 부가 내용 제안은 `권고`이며 권고만으로는 반려하지 않는다. 5는 합치기·경계 조정 과제를 만든다.

가치 감사는 사실 감사가 요구한 조건·예외 문장을 삭제하라고 요구하지 않는다. 같은 문장을 사실 감사는 "예외를 보존하라", 가치 감사는 "줄여라"로 왕복 수정시키는 지적은 서로 상충하는 것으로 보고, 작성자가 원천 기준으로 한 번에 판정한다. 요약(quickAnswer·description)에 본문의 모든 예외를 반복하도록 강제하지 않고, 요약의 범위·조건이 독자에게 오해를 만드는지만 본다.

## 지적표

| 번호 | 심각도 | 원고 위치·인용 | 문제 | 원천·판단 근거 | 권장 조치 |
|---|---|---|---|---|---|

- 심각도: `차단`, `필수 수정`, `권고` (과거 기록의 `중요`는 `필수 수정`으로 읽는다)
- 종류: `내용`(사실의 의미가 달라지는 수정 → 새 독립 검수) / `기계 대조`(행 번호·표기·메타데이터·글자 수 → 수정 뒤 기계 대조로 종결)
- 심각도마다 원문 근거와 독자 영향 설명이 필수다. 실제 의미 오류를 문체로 낮추지 않는다.
- 새 사실을 제안하면 원문 URL과 위치를 요구한다.
- 확인하지 못한 제안은 `보류`이며 원고에 넣지 않는다.
- 모델 다수결이 아니라 현재 공식 원문, 적용 범위, 더 좁고 안전한 표현 순으로 상충을 판정한다.

## 심각도와 판정 — 2026-09-08 개정

| 심각도 | 뜻 | 예 |
|---|---|---|
| 차단 | 독자의 판단·안전·자격·금액·기한을 바꾸는 오류, 핵심 근거 미확보, 실제 모순 | 등급별 입소 자격 조건 누락, 본인부담률 오기, 감경 대상 확대 |
| 필수 수정 | 발행 전 고쳐야 하지만 독자 판단을 바꾸지 않는 오류 | 근거표 행 번호, 요약문 글자 수 초과, 메타데이터 표기 |
| 권고 | 문체·구성·부가 내용 선호 | 문장 길이, 도입부 축약, 추가 설명 제안 |

판정은 넷으로 나눈다.

| 판정 | 조건 | 다음 동작 |
|---|---|---|
| 반려 | 차단 지적이 하나라도 남음 | 작성자가 원천으로 재확인해 수정 → 새 터미널·새 세션 재검수 |
| 수정 후 확인 | 차단은 없고 필수 수정만 남음 | 종류가 모두 `기계 대조`면 수정 뒤 `confirm-findings.mjs`로 대조 증거를 남기고 종결. `내용`이 하나라도 있으면 새 독립 검수 |
| 통과 | 차단·필수 수정 0 (권고는 있어도 됨) | 다음 단계 |
| 실행 보류 | CLI 실패·타임아웃·신호 종료·출력 없음·출력 계약 위반·입력 변경·프로세스 소실 | 인프라 원인 확인 뒤 재실행(별도 상한) |

`수정 후 확인`은 발행 허용이 아니다. 기계 대조 종결은 현재 원고 SHA와 대조 방법을 기록한다. 최초 검수는 전 범위를 한 번에 점검하고, 재검수는 현행 원고 전체·현재 근거·중립적 점검 범위(`--focus`)만 받는다. 이전 판정·대화·통과 예상은 전달하지 않는다.

## 반복 상한과 보류 반환

감사 종류(3단계, 6단계 사실, 6단계 가치)마다 내용 검수는 최초 1회 + 재검수 2회가 상한이다. 실행 보류(인프라 실패)의 재시도는 별도로 2회다. 상한을 소진하면 자동 통과시키거나 계속 돌리지 않는다. 실행기가 `audits/<감사>-hold.md`에 남은 차단·필수 수정 사항, 원인, 수정 범위를 모아 main에 보류로 반환한다. 중요 오류 수정·원천 보완이 끝난 뒤 사용자 지시로 새 작업을 시작하며, `audits/<감사>-hold-resolved.md`에 재개 사유를 적고 `--after-hold`로 재개한다. 경미한 지적마다 사용자 재승인을 요구하지 않는다.

## 실행 안정화

- 감사 시작 전에 원고 스키마 상한·필수 입력·근거 manifest를 검증하고 실패하면 CLI를 시작하지 않는다(`run-audit.mjs` 종료 코드 5).
- 무제한 `until`/`grep` 대기를 쓰지 않는다. `audit-status.mjs --wait`가 runner 생존(PID + 시작 시각)과 마감을 확인하며 유한 시간 안에 끝난다.
- 타임아웃·신호 종료·CLI 실패·출력 없음은 실행 보류로 기록한다. 실행기는 종료 코드가 없으면 만들어내지 않고 `null`로 남긴다. SIGKILL처럼 기록 불가능한 종료는 감독(`audit-status.mjs`)이 `lost`로 확정한다.
- 실행마다 고유 폴더(`audits/<감사>-r<N>/`)를 쓰고 이전 증거를 덮어쓰지 않는다. 기록은 임시 파일 뒤 rename으로 원자적으로 저장한다.

## 독립 검수 기록

각 검수 기록에 실제 터미널 ID, 세션 ID(도구가 발급하지 않으면 비저장 프로세스 실행 ID/PID), 모델·CLI 버전, 시작·종료 시각, 입력 파일과 SHA-256, 전달 프롬프트·원출력 경로, 종료 코드와 판정을 남긴다. 입력을 고정한 뒤 원고를 수정하지 않으며, 결과 회수 시 입력 SHA를 다시 대조한다. 실행 실패·증거 누락·입력 변경은 보류이며 작성자의 자체 검수로 통과 처리하지 않는다. 새 터미널 검수를 생략한 자체 감사는 참고 기록일 뿐 필수 감사 통과를 대체하지 않는다.

## 승인 게이트

세 상태를 섞지 않는다.

1. **자동 감사 최종 판정**: 근거와 가치 검사가 통과했는가.
2. **의료인 승인**: 의료 내용과 표현을 사용자가 임상적으로 승인했는가.
3. **공개 승인**: 외부 공개 최종 동작을 사용자가 승인했는가.

자동 감사가 통과해도 의료인 승인은 기본 `대기`다. 의료인 승인 전에는 `draft: true`다. 공개 승인 전에는 운영 배포나 공개 버튼을 실행하지 않는다.
